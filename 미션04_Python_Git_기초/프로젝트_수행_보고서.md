# Python & Git 기초 프로젝트 수행 보고서

## Git과 함께하는 Python 첫 발자국 - 프롬프트 관리자

이 보고서는 `ia-codyssey` 저장소의 `미션04_Python_Git_기초` 폴더에 있는 실제 코드와 결과물, 증빙 이미지, Git 기록을 기준으로 작성하였다. 보고서 작성 직전에는 `main` 브랜치가 `origin/main`과 같은 `bfa78a5`를 가리키고 있었고 작업 트리는 깨끗한 상태였다. 명령 실행 여부가 기록으로 확인되지 않는 경우에는 완료했다고 추측하지 않고 별도로 표시하였다.

### 1. 프로젝트 개요

#### 1.1 미션 배경

이번 미션의 목표는 Python의 기본 문법으로 콘솔 프로그램을 만들고, 개발 과정을 Git과 GitHub로 관리하는 것이었다. 이전 미션에서 만든 프롬프트를 한곳에서 확인하고 필요한 프롬프트를 빠르게 찾을 수 있도록 프로젝트 주제를 "프롬프트 관리자"로 정했다.

프롬프트는 제목과 내용만 저장하는 것보다 카테고리와 즐겨찾기 상태를 함께 관리할 때 다시 활용하기 쉽다. 따라서 한 개의 프롬프트를 딕셔너리로 표현하고, 여러 딕셔너리를 리스트에 저장하는 구조를 사용하였다.

#### 1.2 프로젝트 목적

프로그램을 만들면서 다음 내용을 실제 코드에 적용하는 것을 목적으로 하였다.

- 리스트와 딕셔너리를 이용한 데이터 관리
- 조건문과 반복문을 이용한 메뉴 및 입력 검증
- 기능별 함수 분리
- JSON과 Markdown 파일 입출력
- Git 커밋을 이용한 단계별 버전 관리
- 별도 브랜치에서 기능을 개발한 뒤 `main` 브랜치로 병합하는 과정

#### 1.3 최종 구현 결과

최종 `main.py`에는 0번 종료 메뉴와 1번부터 13번까지의 기능이 연결되어 있다. 필수 기능인 추가, 목록, 카테고리 조회, 검색, 상세 보기, 즐겨찾기 관리뿐 아니라 JSON 저장·불러오기, 카테고리별 Markdown 내보내기, 수정, 삭제, 조회수 기록과 TOP 목록도 구현되어 있다.

프로그램은 시작할 때 다음 세 개의 프롬프트를 기본 데이터로 준비한다.

| 제목 | 카테고리 | 초기 즐겨찾기 | 초기 조회수 |
|---|---|---:|---:|
| LLM 프롬프트 엔지니어링 글 작성 | 텍스트 생성 | `False` | 0 |
| EchoLens 광고 이미지 제작 | 이미지 생성 | `False` | 0 |
| AI 뉴스 자동화 | 자동화 | `False` | 0 |

- **수행 내용:** `35bea09 feat: add menu input handling`에서 메뉴 입력 처리가 구현되었다. 현재 코드는 `show_menu()`, `get_menu_choice()`, `run_menu_choice()`, `main()`으로 메뉴 표시, 입력, 기능 연결, 반복 실행을 나눈다.

### 5. 프롬프트 관리자 최종 기능

최종 메뉴는 `show_menu()`와 `run_menu_choice()`에서 다음과 같이 연결되어 있다.

| 번호 | 기능 | 연결 함수 | 설명 |
|---:|---|---|---|
| 1 | 프롬프트 추가 | `add_prompt()` | 제목, 내용, 카테고리를 입력하여 새 딕셔너리를 추가한다. |
| 2 | 프롬프트 목록 | `show_list()` | 전체 프롬프트의 번호, 제목, 카테고리, 즐겨찾기 상태를 출력한다. |
| 3 | 카테고리별 조회 | `category_list()` | 현재 데이터의 카테고리를 제시하고 선택한 항목만 출력한다. |
| 4 | 프롬프트 검색 | `search_prompt()` | 제목 또는 내용에 검색어가 포함된 프롬프트를 찾는다. |
| 5 | 프롬프트 상세 보기 | `show_prompt_detail()` | 상세 정보를 출력하고 조회수를 1 증가시킨다. |
| 6 | 즐겨찾기 관리 | `manage_favorite()` | 선택한 프롬프트의 즐겨찾기 상태를 추가 또는 해제한다. |
| 7 | 즐겨찾기 목록 | `show_favorites()` | 즐겨찾기가 `True`인 프롬프트만 출력한다. |
| 8 | JSON 저장 | `save_prompts()` | 현재 `prompts` 리스트를 `prompts.json`에 UTF-8 JSON으로 저장한다. |
| 9 | JSON 불러오기 | `load_prompts()` | `prompts.json`을 읽어 현재 목록을 교체한다. |
| 10 | Markdown 내보내기 | `export_markdown()` | 프롬프트를 카테고리별 `.md` 파일로 내보낸다. |
| 11 | 프롬프트 수정 | `edit_prompt()` | 제목, 내용, 카테고리를 수정하며 빈 입력은 기존 값을 유지한다. |
| 12 | 프롬프트 삭제 | `delete_prompt()` | 번호 선택과 `y/n` 확인 후 프롬프트를 삭제한다. |
| 13 | 조회수 TOP 목록 | `show_top_prompts()` | 조회수를 기준으로 내림차순 정렬하여 출력한다. |
| 0 | 종료 | `run_menu_choice()` | `False`를 반환하여 메인 반복문을 끝낸다. |

메뉴 번호가 위 범위에 없으면 `올바른 메뉴 번호를 입력해주세요.`를 출력한 뒤 메뉴를 다시 표시한다. 기능도 한 함수에 몰아넣지 않고 메뉴, 입력, 추가, 조회, 검색, 즐겨찾기, 파일 처리, 수정·삭제와 정렬 기능으로 나누었다.

### 6. Python에서 사용한 핵심 개념

| Python 개념 | 프로젝트에서 사용한 위치와 역할 |
|---|---|
| 변수 | `choice`, `title`, `content`, `category`, `keyword` 등에 사용자의 입력과 처리 중간값을 저장한다. |
| 리스트 | `prompts`에 여러 프롬프트를 저장하고 `categories`에 기본 카테고리를 저장한다. |
| 딕셔너리 | 한 프롬프트의 제목, 내용, 카테고리, 즐겨찾기, 조회수를 키와 값으로 묶는다. |
| 조건문 | 메뉴 분기, 빈 입력 확인, 번호 범위 확인, 즐겨찾기 상태와 삭제 확인을 처리한다. |
| 반복문 | 메뉴를 계속 실행하고 올바른 입력이 들어올 때까지 다시 질문하며 목록을 순회한다. |
| 함수 | `add_prompt()`, `search_prompt()`처럼 기능을 작은 단위로 분리하여 읽기와 수정을 쉽게 한다. |
| `input()` | 메뉴 번호, 제목, 내용, 카테고리, 검색어, 수정값과 삭제 확인을 입력받는다. |
| 문자열 처리 | `strip()`으로 공백 입력을 걸러내고 `casefold()`로 대소문자 차이를 줄여 검색한다. |
| 파일 입출력 | `with open(..., encoding="utf-8")`으로 JSON과 Markdown 파일을 안전하게 읽고 쓴다. |
| JSON | `json.dump()`로 저장하고 `json.load()`로 불러와 프로그램 데이터로 복원한다. |
| 정렬 | `sorted()`와 `lambda`로 조회수 기준 TOP 목록을 만든다. |
| 예외 처리 | JSON 파일이 없거나 형식이 잘못된 경우 `FileNotFoundError`, `JSONDecodeError`를 처리한다. |

외부 설치가 필요한 라이브러리는 사용하지 않았다. import 목록은 Python 표준 라이브러리인 `json`과 `os` 두 개이다.

| `git merge` | 다른 브랜치의 작업을 현재 브랜치에 합친다. | 두 부모를 가진 `935f98a merge: prompt list feature` 커밋에서 확인된다. | 확인 |

`git remote -v` 결과에서는 fetch와 push가 같은 GitHub 원격 저장소를 사용한다. 원격 계정 정보는 공개하지 않았으며, 보고서 작성 전 상태에서 로컬 `main`, `origin/main`, `origin/HEAD`는 모두 `bfa78a5`를 가리켰다.

### 8. Git 브랜치 활용

프롬프트 목록 기능은 추가 기능 커밋 `228545c` 이후의 별도 흐름에서 개발되었다. 당시 그래프를 간단히 나타내면 다음과 같다.

```text
*   935f98a merge: prompt list feature
|\
| * 7a3770a feat: implement prompt list feature
|/
* 228545c feat: implement prompt add feature
```

`7a3770a`은 증빙 화면에서 `feature/prompt-list` 브랜치로 표시되며, `935f98a`는 `228545c`와 `7a3770a`를 부모로 가진 실제 병합 커밋이다. 즉, 목록 기능을 기존 `main` 개발 흐름에서 분리해 작업한 뒤 병합하여 두 흐름을 하나로 합쳤다.

별도 브랜치를 사용하면 새로운 기능을 개발하는 동안 기준 브랜치를 안정적으로 유지할 수 있고, 병합 커밋을 통해 어떤 기능이 언제 합쳐졌는지도 그래프에서 확인할 수 있다. 현재는 해당 기능 브랜치 참조가 남아 있지 않지만 커밋과 병합 관계는 Git 이력에 보존되어 있다.

관련 증빙은 그림 8의 `07_git_branch_merge.png`와 그림 13의 `12_git_log_graph.png`이다.

### 9. 보너스 기능 구현

#### 9.1 JSON 저장

`save_prompts()`는 현재 `prompts` 리스트를 `prompts.json`에 저장한다. `ensure_ascii=False`를 사용하므로 한글을 그대로 기록하고, `indent=4`로 사람이 읽기 쉬운 형태를 만든다.

#### 9.2 JSON 불러오기

`load_prompts()`는 JSON 데이터를 읽은 뒤 기존 리스트를 `clear()`하고 불러온 데이터로 교체한다. 현재 `prompts.json`에는 `views` 키가 없지만, 불러올 때 각 프롬프트에 `setdefault("views", 0)`을 적용하므로 보너스 기능 추가 전 형식과도 함께 사용할 수 있다. 파일이 없거나 JSON 형식이 잘못된 경우에는 예외를 처리하고 안내 메시지를 출력한다.

#### 9.3 Markdown 내보내기

`export_markdown()`은 카테고리를 키로 하는 딕셔너리에 프롬프트를 묶고 `exports` 폴더에 카테고리별 파일을 생성한다. 공백은 밑줄로 바꾸고 Windows 파일명에 사용할 수 없는 문자는 `_`로 치환한다. 현재 실제 결과물은 `텍스트_생성.md`, `이미지_생성.md`, `자동화.md` 세 개이다.

#### 9.4 프롬프트 수정

`edit_prompt()`는 선택한 프롬프트의 제목, 내용, 카테고리를 수정한다. 수정 입력을 비워 두면 기존 값을 유지하므로 바꾸고 싶은 항목만 선택적으로 변경할 수 있다.

#### 9.5 프롬프트 삭제

`delete_prompt()`는 번호 범위를 먼저 검사하고 `정말 삭제하시겠습니까? (y/n)` 질문을 거친다. `y`일 때만 `pop()`으로 삭제하고 `n`이면 취소하므로 실수로 바로 삭제되는 것을 막는다.

#### 9.6 조회수 기록과 TOP 목록

`show_prompt_detail()`을 실행하면 선택한 프롬프트의 `views`가 1 증가한다. `show_top_prompts()`는 `views` 값을 기준으로 전체 데이터를 내림차순 정렬하여 순위, 원래 번호, 제목과 조회수를 출력한다.

### 11. 문제 해결 과정

#### 11.1 잘못된 입력으로 인한 프로그램 중단 방지

메뉴와 프롬프트 번호를 바로 정수로 변환하면 문자가 입력될 때 오류가 발생할 수 있다. 현재 코드는 먼저 문자열로 입력받고 `isdigit()`과 범위 조건을 확인한 후에만 정수로 변환한다. 제목, 내용, 검색어와 직접 입력 카테고리는 `strip()` 결과가 비어 있으면 반복해서 질문한다. 메뉴와 프롬프트 추가 증빙에서 잘못된 값 이후에도 프로그램이 계속 실행되는 것을 확인할 수 있다.

#### 11.2 기능이 한곳에 몰리는 문제 방지

기능이 늘어나면서 하나의 반복문 안에 모든 코드를 넣으면 읽기 어려워진다. 이를 해결하기 위해 메뉴 출력, 기능 선택, 추가, 목록, 검색, 즐겨찾기, 파일 처리와 보너스 기능을 각각 함수로 나눴다. `main()`은 메뉴를 반복하고 종료 여부만 판단하므로 전체 실행 흐름을 쉽게 확인할 수 있다.

#### 11.3 실행 중 데이터와 파일 데이터의 차이 처리

기본 요구사항의 데이터는 프로그램 실행 중 리스트에 유지되고 종료하면 초기화된다. 필요한 경우에만 8번 JSON 저장과 9번 JSON 불러오기를 사용하여 파일로 보존하도록 선택 기능을 추가했다. 또한 기존 `prompts.json`에 조회수 키가 없어도 `setdefault()`로 0을 넣어 현재 코드에서 사용할 수 있도록 하였다.

#### 11.4 카테고리 이름을 안전한 파일명으로 변환

사용자 정의 카테고리에는 파일명으로 사용할 수 없는 문자가 들어갈 수 있다. Markdown 내보내기에서는 공백을 밑줄로 바꾸고 `< > : " / \\ | ? *` 문자를 `_`로 치환한다. 이 처리로 Windows에서도 카테고리 이름을 이용해 파일을 만들 수 있다.

#### 11.5 독립된 기능 개발과 병합

목록 기능을 `feature/prompt-list`에서 작성한 뒤 `935f98a`로 병합하여 기능 개발 흐름을 분리하였다. 병합 그래프와 두 부모 커밋을 통해 목록 기능이 어느 기준에서 갈라져 다시 합쳐졌는지 확인할 수 있다.

#### 11.6 Git 명령 증빙의 한계 구분

커밋 객체에는 결과가 남지만 `git add`처럼 개별 명령 실행이 항상 기록되는 것은 아니다. 또한 현재 로컬 저장소는 완성된 원격 저장소를 clone한 작업 사본이므로 `origin/main`과 같은 상태만으로 과거 push 명령을 증명할 수 없다. 이 보고서에서는 저장소 상태와 실제 명령 기록을 구분하여 확인되지 않은 명령을 임의로 완료 처리하지 않았다.

### 12. 프로젝트를 통해 배운 점

이번 프로젝트에서는 Python 문법을 각각 연습하는 데서 끝나지 않고 하나의 프로그램 안에서 연결해 볼 수 있었다. 리스트에 여러 딕셔너리를 저장하니 프롬프트를 추가하거나 삭제해도 같은 자료 구조로 목록, 검색, 즐겨찾기와 조회수 기능을 만들 수 있었다.

입력값을 바로 사용하지 않고 `strip()`, `isdigit()`과 범위 조건으로 먼저 검사하는 과정도 중요했다. 잘못된 입력이 들어왔을 때 프로그램이 끝나는 대신 다시 안내하도록 만들면서 반복문과 조건문이 실제 프로그램에서 어떤 역할을 하는지 이해할 수 있었다.

기능을 함수와 커밋 단위로 나누는 방법도 익혔다. `main()`에 모든 코드를 작성하는 대신 각 기능에 이름을 붙여 함수로 분리하니 메뉴와 세부 기능의 관계가 명확해졌다. Git에서도 한 기능씩 커밋하여 변경 과정을 확인할 수 있었고, 목록 기능을 별도 브랜치에서 개발하고 병합하면서 branch와 merge의 목적을 실제 그래프로 확인했다.

마지막으로 JSON 저장·불러오기와 Markdown 내보내기를 구현하면서 메모리에만 있는 데이터와 파일에 남는 데이터의 차이를 경험했다. 코드뿐 아니라 README, 실행 화면과 Git 로그를 함께 정리해야 프로젝트의 수행 과정을 다른 사람에게 정확하게 전달할 수 있다는 점도 배웠다.

### 13. 최종 결과

최종 결과물은 Python 표준 라이브러리만으로 실행되는 콘솔 기반 프롬프트 관리자이다. 세 개의 기본 프롬프트를 시작 데이터로 제공하고, 필수 관리 기능과 사용자 정의 카테고리, JSON·Markdown 파일 처리, 수정·삭제·조회수 보너스 기능을 포함한다.

Git 기록에서는 기능별 커밋, 10개를 넘는 미션 관련 커밋, `feature/prompt-list` 개발과 `main` 병합을 확인하였다. 원격 저장소 연결과 clone 기록도 확인되었다. 다만 기록이 남지 않은 Git 명령은 사실로 추정하지 않고 요구사항 확인표에 별도로 표시하였다.

기존 `main.py`, `hello.py`, `prompts.json`, `.gitignore`, `README.md`, `exports`와 `evidence`는 분석 대상으로만 사용하였으며 이 보고서를 작성하기 위해 내용을 변경하지 않았다. 새로 추가한 결과물은 `프로젝트_수행_보고서.md` 한 파일이다.
