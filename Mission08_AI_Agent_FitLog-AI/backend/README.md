# 로컬 운동 기록 분석

Python 통계 → Python FACTS → Ollama 문장 선택·정리 → 검증 → 화면 순서입니다. 기존 운동 통계 계산은 유지합니다. 최신 기록일 포함 30일을 분석하고 누락일은 휴식으로 만들지 않습니다. 연속일은 분석기간 내 한정이며 날짜 누락에서 끊습니다. 메모는 운동일에 한해 첫 키워드로 단순 분류합니다.

## 실행 설정

기본 주소 `http://127.0.0.1:11434`, 모델 `hermes3:8b`입니다. 이미 설치된 Ollama와 모델을 사용하며 다운로드는 하지 않습니다. 변경하려면 프로세스 환경변수 `OLLAMA_BASE_URL`, `OLLAMA_MODEL`을 설정하고 FastAPI를 다시 실행합니다. 로컬 loopback HTTP 주소만 허용합니다. `.env.example`은 참고용이며 `.env`를 자동으로 읽지 않습니다. 기존 비밀키 파일은 변경하지 않습니다.

기존 Ollama 분석 경로는 OpenAI SDK와 키를 사용하지 않습니다. STEP 12의 별도 POST /api/chat은 코디세이 API를 사용하며 루트 README를 참고하세요. 기존 설치 패키지 목록은 환경 스냅샷으로 남겨두었으며 패키지를 추가하거나 삭제하지 않았습니다.

## 사실과 검증

`workout_facts.py`에서 객관적 수치·단순 비교·기록 관리 안내를 작성합니다. 원문 메모나 인증정보는 모델에 전송하지 않습니다. 메모에 강도 정보가 없다고 단정하지 않고, 이번 분석이 강도 판단을 하지 않는다는 범위만 설명합니다. 동률 활동, 누락일, 이전 기간 0분도 처리합니다.

Ollama 서버의 `/api/chat`에 JSON Schema를 전달합니다(FastAPI의 새 POST /api/chat과는 다른 주소입니다). timeout은 연결 5초/읽기 45초, 재시도와 리다이렉트·환경 프록시 사용은 없습니다. 모델 응답의 네 문자열, 공백, 새 숫자, 외국어, 금지 판단을 검사합니다. 숫자만 같고 의미가 바뀌는 오류도 막기 위해 **각 필드의 허용 문장 선택·결합만 통과**시킵니다. 띄어쓰기 차이는 허용하지만 자유로운 바꿔쓰기는 fallback 대상입니다. 이는 자연스러움보다 사실 보존을 우선한 보수적 구현입니다.

연결 실패, 모델 없음, timeout, JSON 오류, 응답 검증 실패 시 같은 네 필드의 Python 규칙 기반 피드백을 반환합니다. `provider`는 `ollama` 또는 `rules`입니다. 로그에는 고정된 fallback 사유만 기록하며 거부된 생성문이나 비밀정보는 출력하지 않습니다. Firestore 읽기 실패는 기존 503, 빈 기록은 404를 유지합니다.

분석은 버튼 클릭 시에만 실행하며 결과 하단에 생성 방식을 표시합니다. 통계·최근 기록·그래프 갱신은 AI를 자동 실행하지 않습니다. 운동 처방·건강 평가를 제공하지 않습니다.

## 검증

`.venv\Scripts\python.exe -m unittest backend.test_workouts backend.test_analysis backend.test_ai_diagnostics -v`

테스트는 모의 저장소·HTTP 응답을 사용합니다. 기존 OpenAI 전용 진단 테스트는 로컬 모델 검증·fallback 테스트로 교체했습니다. Ollama 분석 통합 검증은 Firestore를 읽기만 합니다. 별도 STEP 12 채팅 E2E는 명시적으로 허용된 경우 conversations에 대화를 저장합니다.
