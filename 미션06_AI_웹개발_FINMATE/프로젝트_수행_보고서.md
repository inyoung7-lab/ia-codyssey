## 1. 프로젝트 개요

FINMATE AI는 투자 초보자가 기업과 투자 정보를 쉽게 이해할 수 있도록 만든 AI 투자 학습 웹 서비스이다. 사용자가 관심 있는 기업명을 입력하면 Gemini가 기업 소개, 주요 사업, 강점, 위험 요소 등을 한국어로 설명한다.

이 서비스는 특정 종목의 매수나 매도를 권유하는 투자 추천 서비스가 아니다. 복잡한 기업 정보를 처음 접하는 사용자가 기업의 특징을 쉽게 공부할 수 있도록 돕는 학습 및 정보 제공 서비스로 기획했다.

기본 AI 기업 분석 기능 외에도 데이터 저장 고도화 보너스 과제로 최근 분석 기업 기록을 브라우저에 저장하는 기능을 구현했다. 사용자 경험 고도화 기능으로는 라이트 모드와 다크 모드 전환을 제공한다.

## 2. 프로젝트 주제

프로젝트 주제는 **투자 초보자를 위한 AI 기업 분석 및 투자 기초 학습 서비스**이다.

주식 투자를 처음 시작하면 기업이 어떤 사업을 하는지, 어떤 장점과 위험 요소가 있는지 파악하기 어렵다. FINMATE AI는 기업명 하나만 입력하면 AI가 핵심 정보를 쉬운 표현으로 정리해주도록 구성했다. 또한 주식, PER·PBR, 투자 위험과 같은 기초 개념을 간단한 카드 형태로 함께 제공했다.

## 3. 프로젝트 목적

프로젝트의 주요 목적은 다음과 같다.

1. 투자 초보자가 기업 정보를 쉽게 이해하도록 돕는다.
2. 사용자가 복잡한 입력 없이 기업명 하나로 AI 분석을 받을 수 있게 한다.
3. 기업의 사업 내용뿐 아니라 강점과 위험 요소를 함께 확인하게 한다.
4. 실제 웹 서비스 구조인 프론트엔드, 백엔드, 외부 AI API 연동 과정을 경험한다.
5. 환경 변수와 서버리스 함수를 이용해 API Key를 안전하게 관리한다.
6. 배포, 실패 처리, 반응형 화면, Git/GitHub 관리까지 포함한 웹 서비스 개발 과정을 수행한다.

## 4. 서비스 기획

FINMATE AI는 한 페이지 안에서 투자 기초 학습과 AI 기업 분석을 모두 사용할 수 있도록 구성했다. 사용자는 상단 메뉴를 통해 홈, 투자 학습, AI 기업 분석, 서비스 소개 영역으로 이동한다.

핵심 사용 흐름은 다음과 같다.

```text
서비스 접속
→ 투자 기초 내용 확인
→ 관심 기업명 입력
→ AI 분석 요청
→ 기업 분석 결과 확인
→ 최근 분석 기업 기록 확인
```

입력 절차를 기업명 하나로 줄이고, 분석 중 상태와 오류 안내를 화면에 표시해 처음 사용하는 사람도 쉽게 기능을 이해하도록 했다. 분석 기록은 서버에 저장하지 않고 사용 중인 브라우저의 localStorage에 간단히 보관한다.

## 5. 타겟 사용자

- 주식 투자를 처음 시작한 투자 초보자
- 기업 분석 방법을 공부하고 싶은 사용자
- 관심 기업의 사업 내용을 쉬운 표현으로 알고 싶은 사용자
- 기업의 장점과 위험 요소를 빠르게 정리해보고 싶은 사용자

## 6. 사용자에게 제공하는 가치

FINMATE AI가 제공하는 가치는 다음과 같다.

- 어려운 기업 정보를 투자 초보자의 눈높이에 맞춰 설명한다.
- 기업 소개뿐 아니라 주요 사업, 강점, 위험 요소를 함께 제공한다.
- 기업명만 입력하므로 사용 방법이 단순하다.
- 분석 중 상태와 오류 안내를 통해 현재 진행 상황을 알 수 있다.
- 최근 분석 기업을 최대 5개까지 확인할 수 있어 어떤 기업을 살펴보았는지 기억하기 쉽다.
- 모바일에서도 같은 기능을 사용할 수 있다.

AI가 생성한 답변은 학습을 위한 참고 자료이며 실제 투자 판단은 사용자가 공식 자료와 최신 정보를 추가로 확인한 뒤 내려야 한다.

## 10. HTML, CSS, JavaScript 역할

### HTML

`index.html`은 서비스의 전체 구조를 담당한다. 홈, 투자 학습, AI 기업 분석, 서비스 소개 영역을 구성하고 기업명 입력 form, 분석 버튼, 상태 메시지, 결과 영역, 최근 분석 기록 영역을 제공한다. 입력창에는 `required`와 `maxlength="100"`을 적용했다.

### CSS

`css/style.css`은 색상, 글자 크기, 카드, 버튼, 분석 결과 영역을 디자인한다. CSS 변수와 `body.dark` 선택자를 이용해 다크 모드를 구성하고, Media Query를 이용해 화면 크기에 따라 메뉴, 카드, 입력창, 버튼, 최근 기록 목록의 배치를 조정한다.

### JavaScript

`js/app.js`은 다음 기능을 담당한다.

- 상단 메뉴의 부드러운 섹션 이동
- 라이트/다크 모드 전환
- 기업명 입력값 검증
- `fetch('/api/analyze')` 요청
- 로딩, 성공, 오류 상태 표시
- AI 분석 결과의 안전한 화면 출력
- 최근 분석 기록 저장, 복원, 중복 제거, 최대 5개 제한, 전체 삭제

AI 결과를 화면에 넣기 전 HTML 특수문자를 처리해 응답 문자열이 그대로 HTML로 실행되지 않도록 했다. 최근 분석 기업명도 `textContent`로 출력한다.

## 11. AI 기업 분석 기능

사용자가 입력하는 값은 기업명 한 가지이다.

입력 예시:

- 삼성전자
- Apple
- NVIDIA

Python 백엔드는 입력받은 기업명을 Gemini에 전달할 프롬프트에 포함한다. 프롬프트는 다음 내용을 한국어로 생성하도록 요청한다.

- 기업 소개
- 주요 사업
- 강점
- 위험 요소
- 초보자 한줄 정리

또한 특정 주식의 매수·매도를 권유하지 않고, 투자 수익을 보장하지 않으며, 확인되지 않은 숫자나 실시간 주가를 알고 있다고 가정한 내용을 만들지 않도록 제한한다.

## 12. 사용자 입력부터 결과 출력까지의 흐름

전체 처리 흐름은 다음과 같다.

```text
사용자 기업명 입력
→ JavaScript 입력값 확인
→ fetch('/api/analyze') POST 요청
→ Vercel Serverless Function
→ api/analyze.py
→ Gemini API 호출
→ AI 기업 분석 생성
→ Python JSON 응답
→ JavaScript 응답 확인
→ 웹 화면에 분석 결과 출력
→ localStorage에 성공 기록 저장
→ 최근 분석 기업 목록 표시
```

프론트엔드는 다음 형태의 JSON을 전송한다.

```json
{
  "company": "삼성전자"
}
```

정상 처리 시 백엔드는 `company`, `analysis`, `model` 필드를 담은 JSON을 반환한다. 프론트엔드는 이 중 `analysis`를 화면에 표시하며, 유효한 분석 결과가 확인된 뒤에만 최근 분석 기록을 저장한다.

## 13. Vercel Serverless Functions

`api/analyze.py`는 Vercel에서 Python Serverless Function으로 실행된다. 주요 역할은 다음과 같다.

1. 실행 환경에서 `GEMINI_API_KEY`가 설정되어 있는지 확인한다.
2. 요청 본문을 JSON으로 읽는다.
3. 기업명이 비어 있거나 100자를 초과하는지 검사한다.
4. 투자 초보자를 위한 Gemini 프롬프트를 만든다.
5. Gemini API를 호출한다.
6. Gemini 응답에서 분석 텍스트를 추출한다.
7. 정상 결과 또는 오류를 JSON으로 반환한다.

`vercel.json`은 `/api/analyze` 요청을 `/api/analyze.py`로 연결한다. 이 구조 덕분에 브라우저는 Gemini API를 직접 호출하지 않고 동일 출처의 서버리스 API만 호출한다.

## 14. API Key 및 환경 변수 관리

Gemini API Key는 HTML, CSS, JavaScript, Python 코드 또는 보고서에 직접 작성하지 않았다.

| 환경 | 관리 방식 |
|---|---|
| 로컬 | `.env`에서 `GEMINI_API_KEY` 관리 |
| Production | Vercel Environment Variables에서 `GEMINI_API_KEY` 관리 |

`.gitignore`에는 `.env`, `.env.local`, `.env.*`가 등록되어 있다. 다음 명령을 이용해 Git 제외 여부를 확인했다.

```text
git check-ignore -v .env
git ls-files .env
```

`git check-ignore`에서는 `.gitignore` 규칙이 확인되었고, `git ls-files .env`에는 결과가 나오지 않았다. 따라서 `.env`는 Git 추적 대상이 아니다. 서버 오류 로그에도 API Key 값 자체는 출력하지 않는다.

## 15. 빈 입력, 로딩 및 API 오류 처리

### 15.1 빈 입력

기업명을 입력하지 않고 `AI 분석` 버튼을 누르면 HTML `required` 검증이 API 요청 전에 제출을 막는다. Chrome에서는 `이 입력란을 작성하세요.`라는 기본 필수 입력 안내가 표시된다.

공백만 입력하는 경우를 위해 JavaScript에서도 `trim()` 결과를 검사한다. Python 백엔드도 빈 기업명을 다시 검사한다.

### 15.2 분석 진행 상태

AI 요청 중에는 다음 동작을 적용한다.

- `AI가 기업 정보를 분석하고 있습니다...` 상태 표시
- 결과 영역에 분석 중 안내 표시
- 분석 버튼 비활성화
- 버튼 문구를 `분석 중...`으로 변경
- 성공 또는 오류 후 버튼을 원래 상태로 복구

### 15.3 API 및 네트워크 오류

네트워크가 끊겨 `fetch`가 실패해도 `Failed to fetch`와 같은 기술적인 영어 오류를 사용자 화면에 직접 표시하지 않는다. 대신 다음 메시지를 표시한다.

```text
네트워크 연결 또는 AI 서비스에 문제가 발생했습니다.
잠시 후 다시 시도해주세요.
```

Chrome DevTools Network를 Offline으로 바꾸어 실제 요청 실패를 발생시켰고, 사용자용 오류 메시지가 표시되는 것을 확인했다. 인증, 사용량 제한, 응답 지연, 서버 오류, 빈 AI 결과, JSON 처리 오류도 상황에 맞는 한국어 메시지로 처리한다.

빈 입력이나 API·네트워크 오류가 발생한 경우 최근 분석 기록은 저장하지 않는다.

## 16. 반응형 구현

CSS Media Query를 사용해 데스크톱과 모바일 화면에 대응했다.

- 900px 이하: 홈 제목 크기와 자간 조정
- 800px 이하: 상단 메뉴 링크 숨김, 학습 카드 1열 배치, 입력창과 버튼 세로 배치
- 600px 이하: 홈 제목 추가 조정, 최근 분석 기업명과 분석 시각 세로 배치

Chrome DevTools Responsive 모드에서 400 × 857 크기로 확인했다. 모바일 화면에서 입력창과 AI 분석 버튼이 화면 너비에 맞게 배치되고 내용이 한 열로 표시되는 것을 확인했다.

## 17. Vercel 배포 과정

배포 과정은 다음과 같이 진행했다.

1. 프로젝트의 정적 파일과 Python API 구조를 확인했다.
2. `vercel.json`에 정적 리소스와 Python 함수 빌드 및 라우팅을 설정했다.
3. Vercel Production Environment Variables에 `GEMINI_API_KEY`를 등록했다.
4. 프로젝트 루트에서 Production 배포를 실행했다.
5. Production alias가 `finmate-ai-gold.vercel.app`으로 연결된 것을 확인했다.
6. 실제 배포 URL에서 기업명을 입력해 Gemini 분석 결과를 확인했다.
7. 보너스 기능 배포 후 최근 분석 기록의 생성, 유지, 중복 처리 및 삭제를 확인했다.

배포 결과:

- Production URL: <https://finmate-ai-gold.vercel.app>
- 기본 AI 기업 분석 동작 확인
- 네트워크 실패 안내 확인
- 최근 분석 기록과 기록 삭제 동작 확인

## 18. 로컬 환경과 Production 환경의 차이

| 구분 | 로컬 환경 | Production 환경 |
|---|---|---|
| 실행 방식 | `vercel dev`를 이용한 로컬 실행 | Vercel Serverless Functions 실행 |
| API Key | 로컬 `.env` | Vercel Environment Variables |
| 접속 주소 | 로컬 개발 주소 | `finmate-ai-gold.vercel.app` |
| Python 함수 | 로컬 Vercel 개발 환경에서 실행 | 요청마다 서버리스 함수로 실행 |
| 로그 확인 | 로컬 터미널 | Vercel 배포 및 함수 로그 |
| 최근 분석 기록 | 현재 브라우저 localStorage | 접속한 브라우저의 localStorage |

최근 분석 기록은 Production 서버나 데이터베이스에 저장되는 데이터가 아니다. 같은 Production URL을 사용하더라도 브라우저나 기기가 다르면 기록이 공유되지 않는다.

## 19. 실제 디버깅 과정

개발 과정에서는 오류 메시지를 바로 코드 수정으로 연결하기보다 다음 순서로 문제를 확인했다.

```text
오류 화면 확인
→ 터미널·브라우저·배포 로그 확인
→ 원인 추정
→ 코드 또는 설정 수정
→ 로컬 재실행
→ Production 재배포
→ 정상 동작 확인
```

### 19.1 Vercel 502 BAD_GATEWAY

로컬 및 배포 환경에서 502 오류가 발생했다. 오류 화면과 실행 로그를 확인한 결과 Vercel의 Python 실행 설정과 프로젝트 구조, Python entrypoint 구성이 원인 후보였다. AI 코딩 도구의 분석도 참고하되 결과를 그대로 적용하지 않고 현재 Vercel 구조와 비교했다. 이후 불필요하거나 맞지 않는 Python 설정을 정리하고 `vercel.json`과 `api/analyze.py` 구조를 수정한 뒤 다시 실행했다.

### 19.2 Python 실행 환경 오류

Python 경로와 entrypoint 관련 오류를 확인했다. 로컬 경로 처리 과정에서 발생한 오류 로그를 읽고 실행 파일 구조를 조정한 뒤 `vercel dev`를 다시 실행해 서버가 시작되는지 확인했다.

### 19.3 Gemini API 요청 오류

Gemini API 요청 과정에서 인증, 모델 접근, 응답 형식과 관련된 오류 가능성을 확인했다. Python 백엔드가 환경 변수에서 Key를 읽고, Gemini REST API에 JSON 요청을 보낸 뒤 응답의 `candidates`, `content`, `parts`에서 텍스트를 추출하도록 수정했다. 응답이 비어 있거나 구조가 예상과 다른 경우도 오류 JSON을 반환하게 했다.

### 19.4 브라우저 캐시 문제

수정된 `app.js`를 배포했는데도 이전 오류 메시지가 계속 나타난 적이 있었다. 배포 코드와 브라우저에서 실행되는 코드가 다른지 확인한 뒤 강력 새로고침으로 캐시를 갱신했고 최신 JavaScript가 반영된 것을 확인했다.

### 19.5 네트워크 실패 테스트

정상 상황만 확인하지 않고 Chrome DevTools Network를 Offline으로 설정해 `/api/analyze` 요청 실패를 직접 만들었다. 이후 사용자 화면에 기술 오류 대신 안내 문구가 표시되는지 확인했다.

이 과정을 통해 AI 도구는 원인을 추정하고 확인 항목을 정리하는 데 도움이 되었지만, 최종 판단은 실제 코드, 로그, 재실행 및 배포 결과를 기준으로 해야 한다는 점을 배웠다.

## 23. 보너스 과제 1 - 데이터 저장 고도화

보너스 과제 1로 localStorage 기반 최근 AI 분석 기업 기록 저장 기능을 구현했다.

### 23.1 저장 데이터

AI 분석 결과 전문을 중복 저장하지 않고 기업명과 분석 시각만 저장한다.

```json
[
  {
    "company": "삼성전자",
    "analyzedAt": "2026-08-14 17:16"
  }
]
```

### 23.2 처리 흐름

```text
기업명 입력
→ AI 분석
→ 분석 성공
→ AI 결과 화면 출력
→ localStorage에 분석 기록 저장
→ 최근 분석 기업 목록 표시
```

### 23.3 구현 조건

- AI 분석 성공 시에만 저장
- 빈 입력, API 오류, 네트워크 오류 시 미저장
- 최근 분석 기록 최대 5개 유지
- 같은 기업을 다시 분석하면 기존 기록 제거
- 동일 기업을 최신 기록으로 맨 위에 배치
- 페이지 새로고침 후 기록 유지
- 기록 삭제 버튼으로 전체 기록 삭제
- 삭제 후 `아직 분석한 기업이 없습니다.` 표시
- localStorage 접근 오류가 기존 AI 성공 화면을 오류 상태로 바꾸지 않도록 예외 분리

동일 기업 비교는 대소문자 차이를 구분하지 않도록 처리했다. 저장 데이터가 손상되었거나 배열 형식이 아닌 경우 빈 기록으로 안전하게 처리하며, 기업명은 HTML 문자열로 실행하지 않고 텍스트로 출력한다.

### 23.4 실제 확인 결과

Production에서 삼성전자, NVIDIA, Apple을 각각 분석해 최근 기록이 만들어지는 것을 확인했다. 새로고침 후에도 기록이 유지되었고, 삼성전자를 다시 분석했을 때 중복 행이 추가되지 않고 가장 최근 위치로 이동하는 것을 확인했다. 기록 삭제 후에는 빈 목록 안내가 표시되었다.

증빙 12번은 분석 결과와 최근 기록 목록을, 증빙 13번은 기록 삭제 후 빈 상태를 보여준다. 최대 5개 제한은 JavaScript에서 배열을 자르는 로직으로 구현했다.

## 24. 보너스 과제 2 - 사용자 경험 UX 고도화

사용자 경험 고도화 기능으로 다크 모드를 구현했다. 상단의 테마 버튼을 누르면 `body`에 `dark` 클래스가 적용되거나 제거되고 버튼 아이콘도 변경된다.

다크 모드에서는 배경, 카드, 글자, 테두리, 그림자 색상이 어두운 화면에 맞게 바뀐다. AI 분석 영역과 최근 분석 목록도 기존 디자인 흐름을 유지하도록 색상을 조정했다.

추가로 다음과 같은 간단한 인터랙션을 적용했다.

- 홈의 주요 버튼 hover 이동 효과
- 투자 학습 카드 hover 이동 효과
- 입력창 focus 표시
- 분석 중 버튼 비활성화 표시
- 기록 삭제 버튼 hover 및 keyboard focus 표시

테마 선택을 localStorage에 저장하는 기능은 구현하지 않았으므로 새로고침 후 다크 모드 선택 유지 기능은 제공하지 않는다.

## 25. 프로젝트를 통해 배운 점

이번 프로젝트를 통해 단순히 화면을 만드는 것과 실제 서비스를 배포해 운영 가능한 상태로 만드는 것은 다르다는 점을 배웠다.

첫째, 프론트엔드와 백엔드의 역할을 구분해 이해할 수 있었다. 브라우저에서는 사용자 입력과 화면 상태를 처리하고, Python 백엔드에서는 API Key를 보호하면서 Gemini 요청과 응답을 처리했다.

둘째, 성공 상황뿐 아니라 빈 입력, 네트워크 중단, 잘못된 응답, 서버 오류도 고려해야 사용자가 이해할 수 있는 서비스가 된다는 점을 배웠다. 특히 기술적인 오류 문자열을 그대로 보여주기보다 상황에 맞는 안내 문구를 제공하는 것이 중요했다.

셋째, 배포 오류를 해결할 때에는 오류 화면만 보고 추측하기보다 로그와 프로젝트 구조를 함께 확인해야 했다. AI 코딩 도구는 가능한 원인을 빠르게 찾는 데 도움이 되었지만, 실제 코드와 실행 결과를 다시 확인하는 과정이 반드시 필요했다.

넷째, API Key는 코드에 넣지 않고 환경 변수로 관리해야 하며 `.gitignore`와 Git 추적 상태를 함께 확인해야 한다는 점을 실습했다.

마지막으로 localStorage 보너스 기능을 구현하면서 저장 시점과 실패 시점을 구분하는 것이 중요하다는 점을 배웠다. 분석 요청을 보냈다는 이유만으로 기록을 저장하지 않고, 유효한 AI 결과를 확인한 뒤에만 기록을 저장하도록 구성했다.

## 26. 최종 결과 및 결론

FINMATE AI는 기획한 핵심 기능인 투자 기초 학습, AI 기업 분석, 사용자 입력과 결과 출력, 실패 처리, 반응형 화면, 환경 변수 보안, Vercel Production 배포를 구현했다. 실제 배포 환경에서 Gemini 분석 결과를 확인했고, Offline 테스트를 통해 네트워크 오류 안내도 확인했다.

보너스 과제 1로 최근 분석 기업을 localStorage에 저장하는 기능을 구현했으며, Production에서 기록 생성, 새로고침 유지, 동일 기업 최신순 처리, 전체 삭제를 확인했다. 보너스 과제 2로 다크 모드와 간단한 UI 인터랙션을 구현했다.

기능, Production 동작, 증빙 01~13과 제출 문서는 제출 가능한 수준으로 준비되었다. 최종 제출 전에는 보너스 기능과 문서 변경사항을 GitHub `main` 브랜치에 최종 반영하고 저장소 동기화 상태를 확인한다.

```text
보너스 기능·증빙·문서 최종 검토
→ 최종 제출 commit
→ git push origin main
→ git status와 GitHub 파일 확인
```

따라서 기능, Production 배포 및 증빙을 기준으로 한 최종 판단은 **제출 요구사항 충족**이다.
